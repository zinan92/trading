# quant-data-pipeline · Data 类首轮试用

- 上游：[`zinan92/quant-data-pipeline`](https://github.com/zinan92/quant-data-pipeline)，源码 `d306095de3c253535e4b47d08b23e9d0f07c01b4`。隔离 SQLite、后端 `127.0.0.1:8000`、Vite 前端 `127.0.0.1:5173`。启动时默认 `PARK_INTEL_URL` 会指向本机别的服务；发现健康页混入该服务事实后，重启并改指向**已停的测试端口** `8112`，最终截图和 API 探针均使用隔离配置。测试完成两服务皆关闭。
- 定位：**多资产数据看板 + 感知信号 + 模拟交易**的混合产品。A 股、美股、加密、商品各有入口；有纸盘买卖，但未见真实券商下单执行，所以不宜当作完整真实交易系统。Data 类仍合适，可加 Paper Trading Dashboard 次标签。
- 证据：[`evidence/probes.json`](evidence/probes.json) 有 20 个原生 API 场景、纸盘买卖记录；原生响应逐项存 `evidence/NN-response.json`，超时场景如实留在探针摘要。[`evidence/screenshots/`](screenshots.md) 保存 **39 张不同截图**：18 张上游原生前端（首页、健康、市场、自选、动量、持仓、搜索、30 张图表中的可见区块、纸盘买卖），21 张辅助 API 证据页。

实测可用：三只 A 股指数的实时展示有数，上证指数 3888.37 与腾讯独立来源相符；美国指数 API 返回 5 个；商品实时 4 个、黄金日 K 10 根；加密 WebSocket 实时 15 品种，BTC 小时 K 10 根、funding rates 6 条。Dashboard 的商品和加密图表实际画出 K 线。隔离模拟账户从 ¥1,000 万开始，先以 1% 仓位买 600519 被正确拒绝（不足买 100 股）；改成 2% 后以 ¥1,237 买入 100 股，现金变 ¥987.63 万、持仓值 ¥12.37 万；同价卖出 100 股后回到 ¥1,000 万、零持仓，两笔历史记录在 UI 中可见。此为**本地纸盘**，绝非真实委托。

失败与空白：`/api/symbols/search?q=600519` HTTP 500，前端搜索没有结果；`/api/index/quote/000001.SH` HTTP 500，而另一个 realtime 入口返回 200，接口契约不一致。A 股指数 K 与茅台个股 K 返回 404，Dashboard 同时提示 9 张图表失败；A 股概念板块返回 200 但 `total=0`，首页“涨幅 TOP20 / 自选热门”为空；隔离库健康页对应 K 线存储 0 条、整体 unhealthy。没有 TuShare token，不应把需要凭证的市场功能推定为已可用。

稳定性：`/api/news/latest?limit=10` 在本轮 25 秒未返回。此后同一单进程中的 perception health/signals 以及先前成功的纸盘读取也连续超时；最终必须结束该隔离后端才能退出。探针文件后半段的纸盘读取超时并不抹去此前买卖成功的证据，而是说明**新闻请求拖住后续响应**的运行故障。原生健康页初次出现的外部 `intel` 数据被排除在评价之外；最终 probe 的 qualitative 显示 unavailable。

阶段判断：商品、加密、美国指数、图表和本地模拟账户具备可验证的产品形态；A 股历史数据、搜索、概念以及新闻/感知链条缺口显著，且单个请求可拖垮后续可用性。最终 Data 类评分与排名待第 14 项完成后统一给出。
