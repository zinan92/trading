## 已验证

在隔离 Python 3.13 环境中，按仓库 `uv.lock` 安装运行依赖，并安装同版本 `czsc==1.0.1` 发行包。发行包内 61 个 Python 源文件与本地 `master` checkout 完全一致；本地 checkout 没有 Rust/Cargo 工具链，无法构建出与提交 SHA 绑定的 `_native` 扩展，因此核心测试实际由 PyPI 1.0.1 wheel 执行。

无需 API 的本地链路可用：固定种子造出 30 分钟 OHLCV，运行行情质量检查、缠论分型与笔分析、信号枚举/参数查询、研究配置、内存研究、落盘 replay、策略回测和 HTML 图表。质量检查还能识别手工注入的一条负成交量。CLI schema 可发现 8 组入口；信号目录共列出 246 个信号。截图 15–18 记录图表、回测统计、实际点击的多空对比页和图表主题切换。

## 风险与边界

按锁定依赖运行的定向测试为 **46 passed / 3 failed / 1 skipped**。3 个失败都集中在关键 BI（笔）输出相对仓库固定基准的漂移：基准要求 43 笔，安装的 1.0.1 Rust wheel 实际生成 31 笔，方向和长度序列也不同；FX 数量和方向基准通过。因为本地 Rust 扩展没有从被测 Git SHA 编译，本轮不能断言此差异来自当前 checkout 还是发行 wheel 与 checkout 的版本漂移；但用户通过 PyPI 安装到的版本确实复现了仓库所写的 parity 失败。

直接从源码目录调用 CLI 会被 `czsc/_native` 的未编译占位目录遮蔽，报 `ImportError: cannot import name 'CzscSignals'`；在仓库外使用已安装 wheel 则可运行。源码安装按 README 需要 Rust 与 maturin，属于实际部署门槛。

回测及图表全部使用 seed=42 合成行情和一个样例多头 Position，不能证明真实市场数据接入、交易收益、信号质量或券商/交易所下单路径。本轮没有调用 Tushare、CCXT 或真实行情接口，也没有任何账户或订单操作。回测图展示的是合成数据下的负结果，应仅作为界面/流程证据。
